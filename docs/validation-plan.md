# Validation plan (real hands and reference solutions)

## 1. Real hand inputs
- Accepted: PokerStars and GGPoker NLHE cash `.txt` hand histories (see `docs/handhistory-design.md`).
- Export: I am not sure of the exact menu names. Check each site's help for "hand history" (PokerStars keeps local hand-history files, with a client setting to save them; GGPoker offers a hand-history download/request in its client or support). Use plain text, English language.
- Place files in `private-data/handhistories/` (git-ignored; verify with `git check-ignore private-data/x`).
- Privacy: real hands are never committed, pasted into issues, or used as test fixtures (fixtures are SYNTHETIC only).
- Aggregate-only check: `cd web && npm run hh:check -- [dir]` prints counts only (parse/reject codes, positions, streets, HU turn/river decisions, invariant failures). It never prints hand text, names, ids or cards; failures show reason code, file index, line number.
- Delete my data: remove the files in `private-data/`; in the app, `DELETE /api/hh` or `DELETE /api/me/data` wipe stored hands.

## 2. Reference-solution formats (local comparison only)
CSV, UTF-8, one spot per file. Header lines start with `#key=value`:
`#board=Ah7d2c`, `#pot=<bb>`, `#stack=<effective bb>`, `#bets_flop=33,75`, `#bets_turn=...`, `#bets_river=...`,
`#oop_range=AhKd:1.0;QcQd:0.5;...` and `#ip_range=...` (combo:weight, weight 0..1).
Then a table with columns: `node_path,combo,action,frequency[,ev]`.
- `node_path`: action history from the root, e.g. `check/bet75/call` (street changes marked `|`, then the dealt card).
- `combo`: two cards, e.g. `AhKd`; `frequency` in 0..1, summing to 1 per (node, combo); `ev` optional, in bb.
- PioSolver and GTO Wizard exports: converters will be written once the user provides a sample file. Not guessed here.
- Licensing: third-party solution data must not be redistributed or committed (keep in `private-data/reference/`). It is used only for local comparison. Our shipped library is generated by our own solver.

## 3. How validation is measured
Measurable:
- Exploitability of our own solution per spot (best-response value in our tree, % pot). Needs no reference.
- Strategy distance vs reference: mean absolute frequency difference per node, weighted by range reach (combo weight times the probability of reaching the node), reported per street and per node depth. Only on nodes present in both trees.
- Action-level agreement: top-action match rate; EV difference if the reference gives EVs (compare in bb, same pot and stack).
- Real hands: the share of hands analysable (HU turn/river) and, per decision, our EV loss. This tests plumbing and plausibility, not correctness.
Not measurable:
- Our strategy's EV loss against the reference's best response. That needs the reference's full tree and strategy for all nodes, which an export does not give us.
- Correctness of ranges inferred from real hands: they are approximate, so a disagreement may come from the range and not from the solver.
- Close distance to a reference does not prove our solution is right (the reference has its own abstraction and convergence error). Report the reference's own exploitability if given.
